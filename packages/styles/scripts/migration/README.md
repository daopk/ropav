# The `@apply` codemod

Temporary, like everything else named `migration`. It exists to take Tailwind out of the two
published packages without anyone deciding, by hand, what 1,430 `@apply` statements meant.

```bash
node scripts/migration/codemod.mjs --files=components/button.css   # one file
node scripts/migration/codemod.mjs                                 # all of them
node scripts/migration/codemod.mjs --dry                           # and put them back
```

## The shape of it

**`oracle.mjs`** asks Tailwind. It builds a throwaway stylesheet with one rule per distinct
argument list, compiles it with the CLI the bundle already uses, and re-roots each result onto
`&`. Every Tailwind variant is written relative to the element, so the responsive and state
variants, the arbitrary values, the `-(--token)` references and the `inline` theme substitutions
all come back correct with no rule here to handle any of them — `rounded-component` returns
`var(--component-radius, calc(var(--radius) * 3))`, which is the substitution, not the alias.

**`normalise.mjs`** does the only two things that are not Tailwind's answer verbatim: it drops a
`--tw-*` slot nothing reads, and renames the rest to `--rp-*`. It does *not* fold them away. A
slot is how two rules that both match an element combine, and folding one into a literal drops the
other's contribution — silently, in a state nobody was looking at. Dissolving a group is a change
of behaviour and belongs to the step that owns it.

**`writer.mjs`** splices byte ranges. These stylesheets carry more comment than rule, and the
comments are why they can be read at all; no CSS printer preserves them, so nothing here parses
the file.

**`verify.mjs`** compiles the whole entry before and after and compares the `components` layer
rule by rule, with the normalisation applied to both sides. Only an empty diff leaves the edit on
disk; anything else restores every file and prints what moved.

**`slots.css`** was generated by the run, and no longer is. The renamed slots need their
`@property` registrations or they are undefined custom properties, and a declaration reading one
becomes invalid at computed-value time — `border-style: var(--rp-border-style)` quietly computes
to `none` and takes the border with it. Which slots to register was read off the `@apply` corpus,
which expanding it removed; a run over the statements that survive classifies only the few they
name, and writing that out leaves a file with one block in it. The set lives in `slots.css` now.

**`ring.mjs`** collapses the five-slot `box-shadow` to `var(--rp-ring), var(--rp-shadow)`. It is
the step the note in `normalise.mjs` defers to: the slots stay as the parameters of a ring, so a
rule can still re-parameterise a ring another rule composed, and only the composite folds.

## Both checks, because one is not enough

The rule-by-rule diff cannot see the failure above. It compares *declarations*, and the
declarations were identical; what changed was whether they resolved. That is what
`packages/ropav/tests/styles/migration` is for — it renders every rule and reads back the computed
value, and it caught exactly that on the first file this was run against.

Run them together. The diff says the codemod transcribed faithfully; the golden says the browser
agrees.
